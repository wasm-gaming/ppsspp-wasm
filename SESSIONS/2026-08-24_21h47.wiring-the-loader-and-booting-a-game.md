**The seam, as built.** `PpssppModuleInit` carries `canvasSelector`; the loader writes it
into `Module.ENV` **from `preRun`**, and that timing is the finding of round 28 rather
than a preference: `__emscripten_environ_constructor` is
`__attribute__((constructor(100)))`, so the environment C sees is copied out of `ENV`
inside `__wasm_call_ctors`, which `initRuntime()` calls while the module is still being
built. A write after `await create(...)` looks equivalent and is a write nobody reads.

**The bridge's shape.** One function on one thread: `PpssppWeb::Frame()` runs from
SDLMain's Emscripten main loop, which is the browser's main thread. Everything
observable is polled there; what other threads produce is queued under a mutex and
drained there. There is no `MAIN_THREAD_ASYNC_EM_ASM` anywhere, and adding one is the
wrong way to extend it.

**The contract still needs no emulator.** 42 runtime tests, the compile-time conformance
suite and the demo all run against `tests/fake-module.mjs` with no `.wasm` anywhere.
`make test` is the whole of it.

**The instrument has eight fakes and eight verdicts**, `make smoke-selftest` runs them
locally in about a hundred seconds, and two of them are a *pair*: `draws/` and
`transparent/` differ in one argument, the alpha they clear with. `DRAWING, BUT
TRANSPARENT` is a red verdict. The smoke test itself still only runs in CI, because the
artifact download is refused for this account's sessions.

**A warm round costs about eight minutes** end to end — 2m35s–3m10s of upstream
checkout, ~1m30s of build, ~1m40s of selftest, 10s of smoke. The upstream checkout is
now the largest slice by a wide margin, and it is larger than the build. A *new branch's
first* round cost 14 minutes with both caches cold.

## The pending register

Superseding every `Next` in the closed file.

### Blocking the port from being usable

1. **Wire the real loader and drop the demo's stub** — the first moment the two halves
   of this repository actually touch. `make site` will need to carry `dist/native/`; it
   copies `dist/*.js` only, so the glue would 404 where `src/loader.ts` looks for it.
   The `.data` bug from the first session is the standing argument for doing this: the
   stub is why nobody found it.
2. **Boot a game.** Everything measured so far is PPSSPP's own UI. The smoke test runs
   `callMain([])` and drives no input, so nothing past the menu has ever been exercised.
3. **Fire an event, any event.** `booted`, `fps`, `pause`, `exit` and `saveState` are
   written, exported and unexercised — a smoke run boots no game, so `booted` and `fps`
   *cannot* fire and the rest need input nothing drives. `booted` is the one with a hard
   requirement: it resolves the promise `start()` returned, and an engine that never
   emits it leaves a host waiting forever. This is now the largest unmeasured thing in
   the port, and item 2 is what would first exercise it.
4. **`ppsspp_web_pause`, `resume` and `shutdown` have never been called.** The settings
   half of the bridge is measured; these three are not. `pause`/`resume` are guarded on
   `PSP_IsInited()` and would be no-ops in the menu anyway; `shutdown` ends the main
   loop, which would end a smoke run — so exercising them needs a session, not a smoke
   round.

### Owed to the instrument

- **A reference frame.** `DRAWING` still means more than one colour. A build rendering a
  field of corrupted garbage passes it. There is no golden image and no tolerance for
  SwiftShader, and neither is worth building until something is worth comparing against
  — but a booted game is exactly that something, so this may stop being deferrable
  alongside item 2.

### Owed, not blocking

- **Cache the upstream checkout in CI.** Now the largest slice of a warm round at
  2m35s–3m10s, against a build of about 1m30s. This has moved from "worth doing" to
  "the only slice left worth attacking".
- **Seed the Actions cache from the default branch.** Branch-scoped caching cost a full
  cold round on the first push to a new branch: 14 minutes against a warm 8.
- **Read the ccache hit rate.** The job prints it and nobody has looked. Round 27 ran a
  7m45s build with *both* caches reporting an empty restore, which is far short of a
  genuinely cold build — so something was warm that the cache steps do not account for,
  and one look would settle it.
- **Settle the pool default with evidence.** `poolSize()` returns
  `Math.max(4, hardwareConcurrency ?? 4)`; eight was not enough *while the main thread
  blocked*, and it no longer does. A round at pool 4 is the measurement, and the
  comment's reasoning needs replacing either way: the constraint is correctness, not
  throughput.
- **Rule out UPnP.** It starts a thread even with `USE_MINIUPNPC=OFF`, and it was among
  the last things logged before three different failures. Three coincidences are not
  evidence, and it is one line in the CMake block to eliminate.
- **The preloaded assets carry an absolute host path** —
  `…/emsdk/upstream/emscripten/cache/sysroot/share/ppsspp/assets`. Self-consistent; a
  fixed `/assets` would be portable.
- **`--loglevel=4` is also stat'd as a path**: `IsDirectory: stat failed on
  --loglevel=4`. Harmless — the flag parses and applies — but PPSSPP hands unrecognised
  leftovers to the boot-file logic.
- **`MASKED_PSP_MEMORY` is redefined** on every GPU translation unit. Upstream's, noise
  rather than a defect.
- **The dist-tag question.** `release.yml` defaults to `next` because the package cannot
  start a session in a browser yet. If anyone depends on this before it can, prerelease
  versions are the better answer.

### Known and deliberately not pending

- **The upstream patches stay here.** Decided in the first file and not reopened: the
  reason is authorship, and the cost — permanent re-application on every `REV` bump — is
  recorded there rather than re-argued.
- **The window-creation property is the better shape and stays unbuilt.** SDL3 also
  resolves `SDL_PROP_WINDOW_CREATE_EMSCRIPTEN_CANVAS_ID_STRING` on
  `SDL_CreateWindowWithProperties`, which would be per window rather than per process —
  a closer fit to a package that builds a canvas per session. It needs a patch to
  PPSSPP's own window creation, and the hint works. Revisit only if the hint stops being
  enough.
- **The local build's Emscripten ports are a sandbox workaround, not repository state.**
- **The twelve other engines, networking, video in UMD titles, a WebGPU backend.** Out
  of scope, as they have been since the first session.
