## Where this repo actually was

`main` at the end of the previous file. The facts a next session should not have to
re-derive:

**The port runs and draws.** Round 26, green: 1552 distinct colours in a screenshot of
what the browser displays, 160684 draw calls over two minutes, the Logo screen handing
over to the main menu. Twelve patches applying cleanly onto the pinned revision from a
clean `make native-checkout`.

**The contract is done and does not depend on any of that.** 41 runtime tests, the
compile-time conformance suite and the demo all run against `tests/fake-module.mjs` with
no `.wasm` anywhere. `make test` is the whole of it and needs no browser.

**A build round costs about nine minutes** — 2.5 min of upstream checkout, 2–3 min of
warm build, 3.5 min of smoke. The first round on a *new branch* costs seven minutes more,
because the Actions cache is branch-scoped. `DEBUG=1` is link-only and costs a relink;
`GLTRACE=1` and `FRAMETRACE=1` are compile defines scoped to one file each, so they cost
one object.

**The smoke test only runs in CI**, and not for convenience: the artifact download is
refused for this account's sessions, so the emulator and a browser cannot be put in the
same place by hand. `make smoke-selftest` needs no emulator and does run locally, which
is what makes the instrument itself cheap to change.

## The pending register

Superseding every `Next` list in the closed file.

### Blocking the port from being usable

1. **Explain the pixel sampler's disagreement, or prove a host cannot hit it.** The
   screenshot shows 1552 colours; the in-page `drawImage` sampler reads the same canvas
   as having no opaque pixel. The leading explanation is the context attributes —
   `alpha: true` with `premultipliedAlpha: true`, so a drawing buffer left at zero alpha
   contributes nothing when *we* composite it — but SwiftShader's handling of `drawImage`
   from a WebGL canvas would fit too, and **neither has been established**. This matters
   beyond the instrument: a host that composites this canvas the way the sampler does
   would see the same nothing. `SDL_GL_SetAttribute(SDL_GL_ALPHA_SIZE, 0)` under
   Emscripten is the obvious experiment, and it belongs in the port rather than the
   harness — forcing it in the harness would turn the smoke test green while everything
   the package ships stayed broken.

2. **Give SDL3 a canvas it can find.** Its Emscripten driver resolves
   `SDL_HINT_EMSCRIPTEN_CANVAS_SELECTOR`, defaulting to `#canvas`, and fails window
   creation when nothing matches. The smoke harness uses that id to test one thing at a
   time; the SDK cannot, because it builds a new canvas per restart and they cannot all
   share an id. Cheapest shape scouted: export `ENV` and set
   `SDL_EMSCRIPTEN_CANVAS_SELECTOR` before `callMain` — one more name in
   `-sEXPORTED_RUNTIME_METHODS`, no new C. Either way it is a change to `src/module.ts`,
   **and that is where it must be declared first.**

3. **The bridge, and `-sEXPORTED_FUNCTIONS`.** Design scouted in the source, not written:
   - `Core/Config.cpp` already has the table this needs — `g_sectionMeta`, mapping
     `"Graphics"` and friends to their `ConfigSetting` arrays — and
     `ConfigSetting::ReadFromIniSection()` already applies a value from an ini section. A
     function beside that table taking `Section`, `Key` and a string is the whole of the
     settings half.
   - A new EMSCRIPTEN-only source holds the four `ppsspp_web_*` symbols with
     `EMSCRIPTEN_KEEPALIVE`, plus the event callback. Events must reach
     `Module.ppssppEvent` from threads that are not the main one, so
     `MAIN_THREAD_ASYNC_EM_ASM` rather than a plain `EM_ASM`.
   - `Web/FastForward` has no ini entry — it is this package's own key and sets the
     throttle, not a config field.
   - `booted` is the one event with a hard requirement: emitted when the first frame is on
     its way, not when `main()` starts, because it is what resolves `start()`.

4. **Wire the real loader and drop the demo's stub** — the first moment the two halves of
   this repository touch. `make site` will need to carry `dist/native/`; it copies
   `dist/*.js` only, so the glue would 404 where `src/loader.ts` looks for it. The `.data`
   bug from the first session is the standing argument for doing this: the stub is why
   nobody found it.

5. **Boot a game.** Everything measured so far is PPSSPP's own UI. The smoke test runs
   `callMain([])` and drives no input, so nothing past the menu has ever been exercised.

### Owed to the instrument

- **A selftest case that binds the default framebuffer.** Six cases stayed green through
  rounds 18–23 while `drawsToCanvas` and `clearsToCanvas` were meaningless, because none
  of them ever binds it: a predicate that never fires and a fake that never triggers it
  agree with each other. This is the gap that let a wrong number survive six green runs.
- **A reference frame.** `DRAWING` means more than one colour. A build rendering a field
  of corrupted garbage passes it. There is no golden image and no tolerance for
  SwiftShader, and neither is worth building until something is worth comparing against.

### Owed, not blocking

- **Cache the upstream checkout in CI** — 2.5 minutes, now the largest slice of a warm
  round.
- **Seed the Actions cache from the default branch.** Branch-scoped caching cost seven
  minutes on each of three new branches in one day.
- **Settle the pool default with evidence.** `poolSize()` returns
  `Math.max(4, hardwareConcurrency ?? 4)`; eight was not enough *while the main thread
  blocked*, and it no longer does. A round at pool 4 is the measurement, and the comment's
  reasoning needs replacing either way: the constraint is correctness, not throughput.
- **Rule out UPnP.** It starts a thread even with `USE_MINIUPNPC=OFF`, and it has now been
  among the last things logged before three different failures. Three coincidences are
  not evidence, and it is one line in the CMake block to eliminate.
- **The preloaded assets carry an absolute host path** —
  `…/emsdk/upstream/emscripten/cache/sysroot/share/ppsspp/assets`. Self-consistent; a
  fixed `/assets` would be portable.
- **`--loglevel=4` is also stat'd as a path**: `IsDirectory: stat failed on --loglevel=4`.
  Harmless — the flag parses and applies — but PPSSPP hands unrecognised leftovers to the
  boot-file logic.
- **`MASKED_PSP_MEMORY` is redefined** on every GPU translation unit. Upstream's, noise
  rather than a defect.
- **The dist-tag question.** `release.yml` defaults to `next` because the package cannot
  start a session in a browser yet. If anyone depends on this before it can, prerelease
  versions are the better answer.

### Known and deliberately not pending

- **The upstream patches stay here.** Decided in the closed file and not reopened: the
  reason is authorship, and the cost — permanent re-application on every `REV` bump — is
  recorded there rather than re-argued.
- **The local build's Emscripten ports are a sandbox workaround, not repository state.**
- **The twelve other engines, networking, video in UMD titles, a WebGPU backend.** Out of
  scope, as they have been since the first session.
